# PWorks Login and Session Management

Reactive Spring Boot service that signs users in through Google, Microsoft, or Apple
and manages a short-lived session that shows the signed-in user's email and full name.

Maven artifact: `parra-works-web` · base package: `com.pworks.web.app.pww`

## Project Status

The project is a working skeleton. Sign-in is not wired yet.

| Area | State |

| Session handling, home page, sign-out | Not started |

## Architecture

```text
User (browser)
     │
     ▼
PWorks app  ── Docker container, Spring WebFlux
     │
     ▼
Security module ── Spring Security OAuth 2.0 / OpenID Connect client
     │
     ▼
Identity providers: Google · Microsoft · Apple
```

Sign-in flow:

1. The user opens the app and picks an identity provider.
2. The security module redirects to that provider.
3. The provider returns the user's email and full name.
4. The app stores them in a session and shows the home page.

## Features

Planned for the first milestone:

- Sign in with Google, Microsoft, or Apple
- Home page displaying the signed-in user's email and full name
- Sign out button that closes the session
- Session expiry after 5 minutes
- In-memory session store, single instance

## Prerequisites

- JDK 25
- Maven, or a repaired Maven wrapper (see [Getting Started](#getting-started))
- Docker with Docker Compose — only needed once `compose.yaml` defines services

## Getting Started

### Run

```bash
mvn spring-boot:run
```

The app starts on <http://localhost:8080>; for now it only renders the default
error page, since no controllers or templates exist.

> The wrapper is currently incomplete: `.mvn/wrapper/maven-wrapper.properties` is
> missing, so `./mvnw` fails. Restore it with `mvn -N wrapper:wrapper` (or by
> re-exporting the project from Spring Initializr) and the wrapper commands below
> work:
>
> ```bash
> ./mvnw spring-boot:run
> ```

### Docker Compose

```bash
docker compose up --build
```

`compose.yaml` has no services yet, so this does not start the application. An app
service is added in a later milestone.

### Try it

Not available yet. Once security is wired:

1. Open <http://localhost:8080>.
2. Choose Google, Microsoft, or Apple.
3. Complete the provider's sign-in flow.
4. The home page shows your email and full name.
5. Use the sign-out button to close the session.

## Configuration

No OAuth client is configured yet. `application.yaml` currently sets only the
application name:

```yaml
spring:
  application:
    name: parra-works-web
```

Credentials and client IDs will come from environment variables, bound through
Spring Boot relaxed binding to
`spring.security.oauth2.client.registration.{provider}.*`.

| Variable | Description |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `MICROSOFT_CLIENT_ID` | Microsoft Entra ID application (client) ID |
| `MICROSOFT_CLIENT_SECRET` | Microsoft client secret |
| `APPLE_CLIENT_ID` | Apple service ID |
| `APPLE_TEAM_ID` | Apple developer team ID |
| `APPLE_KEY_ID` | Apple private key ID |
| `APPLE_PRIVATE_KEY` | Apple private key (PEM) |

> Never commit client secrets, keys, or tokens. Use environment variables or a
> git-ignored local file.

## Session Behavior

Planned, not implemented yet:

- Created on successful sign-in and holds the user's email and full name.
- Expires after 5 minutes, set by `server.reactive.session.timeout=5m` in
  `application.yaml`.
- Stored in memory only: sessions are lost on restart and are not shared across
  instances.
- Extending a session from a frontend dialog is planned; no endpoint exists yet.
